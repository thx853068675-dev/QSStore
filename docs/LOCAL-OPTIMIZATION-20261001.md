## 按 review 顺序完成的改动

| 顺序 | 优化 | 当前实现与验证 |
|---|---|---|
| 1 | 多安装包更新目标 | 管理页按实际 bundle 与所选 asset 发起更新，避免同仓库第二个应用误装主包；目标变化或存在歧义时提示重新选择。管理页次级包更新回归通过。 |
| 2 | 卸载重装安全性 | 普通应用先完整传输新包并核对摘要，再核实用户确认的旧应用版本、证书指纹和 appIdentifier，最后执行卸载与安装。传输失败、身份改变或卸载前取消均保留旧应用。设备暂存票据写入任务数据库，未完成清理可以在重连后继续。 |
| 3 | 全局安装队列与弹窗 | 新增进程级 `InstallCoordinator`，页面提交任务、共享状态。新任务按原始入队时间串行执行；完成记录允许显式重新安装。调度锁持续到真实调用结束，超时或界面取消不会提前放行另一个签名/安装任务。无线调试与清除数据确认由当前可见页面接管。 |
| 4 | HAP 清单解析边界 | 普通 HAP 的 `pack.info`、`module.json` 在读取前限制展开大小为 4 MB，拒绝重复、加密条目，避免小压缩文件触发大内存分配。超大清单与重复条目回归通过。 |
| 5 | 服务端包元数据缓存 | 按可信 SHA-256、包类型和解析修订缓存应用身份、图标及压缩包内候选项；重复选择同一 ZIP 的不同包不再次下载。限制 512 条/64 MB、单条 4 MB；损坏缓存按未命中处理，不保存整包或凭证。 |
| 6 | 后台采集与限流恢复 | 用户检查更新、定时采集和管理员批量同步进入持久队列，同一应用请求合并；准备草稿、补全目录、刷新各获得执行机会。刷新失败最多尝试四次并退避，遵守 GitHub 冷却时间。详情页区分等待、完成和失败，后台尚未完成时不会误报“已是最新”。 |
| 7 | 目录查询减负 | 应用列表与“我上架的应用”批量读取图标、上架者、版本、资产和计数。30 个应用的测试目录只执行 7 条读取 SQL，逐条输出与原详情查询一致。 |
| 8 | 账号轮询去写库 | 已核验昵称、头像五分钟内未变化时不执行数据库查询或更新；真实变化才同步评论与上架者信息。回归中连续 20 次相同账号轮询产生 0 条 SQL；缺失头像或账号 ID 回退不会抹掉已有公开资料。 |
| 9 | HTTP 条件缓存与共享配额 | 公开目录、详情、版本和评论使用 ETag/304；图标修订地址可长期缓存。私有接口保持 no-store。客户端公开缓存限制 64 项/8 MB。GitHub API 条件缓存隔离凭证和 Accept 类型，同一凭证耗尽配额后跨仓库共享冷却。 |
| 10 | APP 解析、存储与清理 | APP 预览、图标、权限读取复用解包结果，文件变化则失效；缓存最多两个 APP、合计 512 MB，大单包独占。导入、解压、签名前检查剩余空间。完成任务文件保留最多 24 小时或合计 512 MB，保留安装身份记录；取消和回收先记录清理日志，保护其他任务仍引用的文件。 |
| 11 | 账号恢复与错误内容处理 | `AccountService` 合并并发刷新，401 静默刷新最多一次；迟到刷新不会恢复已退出账号。账号失效、网络、权限与存储问题分别处理。下载到 HTTP 200 的错误包时删除错误内容并尝试下一来源，最后一次网络失败保留真实断点。 |
| 12 | 文档、依赖与回归门禁 | 更新根 README、原生任务生命周期及服务器 API，锁定 Python 依赖，新增本地/CI 共用的 `tools/check_local.py`。GitHub Actions 配置仅保存本地，未在远程执行。门禁没有发布、账号登录或证书申请步骤。 |

主要入口：客户端 `native/entry/src/main/ets/jobs/InstallCoordinator.ets`、`NativeJobRuntime.ets`、`JobStore.ets`、`PackageArchive.ets`；服务端 `server/hapstore/artifact_cache.py`、`db.py`、`submissions.py`、`collector.py`。

## 验证范围与实际限制

1. 本轮没有实机测试。后台调度、断连后设备暂存清理、无线调试页面切换与卸载重装仍需要设备验证；主机回归不能证明系统后台权限或真实设备安装成功。
2. 预传包可以减少“旧版卸载后还要下载或传输”的风险，系统卸载和安装不是事务。卸载已经完成后，系统拒绝安装或设备离线仍可能使应用暂时缺失；不能承诺原数据回滚。
3. 自更新继续使用现有设备端独立替换路径并预先备份签名身份。普通应用的预传替换改进不等于本轮已经验证跨证书自更新。
4. APP 缓存以沙箱文件大小、修改时间和纳秒修改时间判定失效；实际摘要与包身份验证仍独立执行。远程暂存票据尚未返回前发生断连时，原生层只能尽力清理，该阶段无法保证设备无残余。
5. 服务端新表随启动幂等创建，优化尚未部署。后台刷新状态需要配套服务端；新版客户端兼容旧同步刷新响应，旧客户端不会自动等候新后台采集完成。部署前应备份数据库与身份加密密钥。
6. 管理员指定单仓库的诊断同步仍同步执行，普通用户刷新、周期采集和管理员批量同步均已排队。CI 仅完成配置与本地对应门禁验证，未实际触发远程工作流。
