# 51 预览版标签与 OHcode 识别修复

## 修复

- 原生 Text 省略文字后仍保留 40% 限制宽度。现在先使用当前 UIContext 的真实字形宽度选出可显示文本，再按可见字形与 8 vp 水平留白设置背景宽度；按 Unicode 码点截断，完整版本仍供无障碍读取。
- 发现页标签高 12 vp；详情页按照原有标题字号 25/17 同比例调整字号、高度，背景高约 17.65 vp。背景、文字反色规则保持一致。
- 发现页超过宽度的名称使用系统 Text 跑马灯，边缘渐隐；按反馈将 step 从 0.35 提升至 0.55，启动间隔从 1800 ms 调整为 1200 ms。仅可见单行标题启用，保留右侧版本和操作区域。详情页仍使用两行标题。
- 星星数与下载量分别使用浅色背景，与分类标签保持相同上下留白和圆角；星空卡片使用半透明浅底。
- 缺少有效包身份的发现页条目打开详情，避免显示无法查询的「安装/更新」和创建无下载地址的任务。
- 发现页和管理页的卡片操作使用普通圆角按钮，半径统一 14 vp，保留 44 vp 触摸高度和状态颜色。

## 分页

- 原先触底才请求下一页；现在接近页尾约 6 个应用时预取，列表预布局缓存为 4 项，不提前遍历所有服务端页面。
- 原先每次追加都按星数重排全部已加载卡片，新页的高星应用插到上方会改变正在浏览的位置。现在只对新页排序并追加，按应用 ID 去重，保留已有卡片的顺序和对象。
- 新页只刷新新应用的版本频道、安装状态和图标，保留已识别版本；每批图标传输和解码限制为 4 路。输入关键词变化后不再调度旧关键词剩余图标。
- 续页失败保留已有卡片，在固定高度页尾提供重试；失败期间停止自动请求，避免滑动重复打请求。依据服务端页码与总数判断结束，防止跨页去重后无限续取。
- 新增测试覆盖分页不移位、跨页去重、预取边界、失败重试、增量状态不丢失和图标并发限制。

## OHcode

- GitHub Release 附件大小 752,209,204 字节，超过原有 300 MiB 全包解析上限；服务端包名为空、内部编号为 0，任何本机刷新都无法关联。
- 新增大 HAP 官方 Range 清单读取：首次通过 GitHub 官方资产 API，后续通过同一官方 CDN 地址；限制最多 8 MiB、48 次请求和 30 秒请求预算。校验范围、长度和 ETag；HTTP 200 在读取正文前拒绝。跳转限制为官方域名，账号令牌不传往 CDN。
- 不提高全包下载上限，不通过第三方镜像读取部分包，不宣称部分内容完成整包 SHA-256 校验。成功结果按 GitHub 摘要单独缓存为 `hap-range`；后续同步复用，客户端实际安装仍解析完整包。
