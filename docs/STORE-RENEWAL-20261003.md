## 已实现

- 管理 → 已安装卡片增加「续签」，应用信息页增加「商店续签」和「选择原包」。纯本地侧载保留手动续签。
- 商店续签进入原有签装流程页并自动入队，不打开文件选择器，不依赖页面停留来维持下载/安装。
- 精确按包名和已安装内部版本号取回原包，不使用当前正式/预览频道的新版本代替原版本。
- 已有成功安装记录时保持附件类型、下载地址、镜像及 ZIP 内包选择标记；可复用已留存、摘要验证通过的原包缓存。新签名输出使用独立路径，不覆盖原签名文件。
- 没有线上安装记录的关联应用只读取商店历史元数据，核对正式、预览两种渠道。最多每种渠道 5 页、每页 50 条；不会触发 GitHub 重采，不由服务器代理 HAP 文件。
- 原包未采集身份、已安装版本缺失、同版本多个类型不能唯一确认或历史超过核对上限时，明确引导手动选择同版本文件；不猜测附件，不静默升级。
- 同一应用重复点击、多个入口同时操作合并为同一来源查找和同一持久任务。暂停后的重复进入保留原请求、已准备材料及进度。
- 正在更新/安装时阻止创建第二个续签任务，避免替换已有队列内容。
- 无账号时明确进入等待登录状态。无线调试未连接时沿用全局连接弹窗和任务恢复。
- 切换为手动选包只在用户确认提交后清理暂停的商店续签任务，避免残留两份续签任务。仍在执行时不允许替换；只打开或取消文件选择器不会清理任务。
- 即使复用缓存、恢复逻辑跳过普通解析阶段，申请签名材料前仍重新检查实际包名及内部版本号。
- 续签继续使用第一步的新 Profile、期限增加、覆盖兼容性、禁止卸载及 updateTime/证书指纹确认保护。
- 管理及应用信息页显示已完成的「上次续签至」日期。它表示本工具最后一次已确认的续签结果；未掌握授权材料的应用显示「授权有效期未知」，不把其他工具可能重新签装的现状推测成准确期限。
- 实测补修：当前目录的包名身份缺失或变化时，成功的线上安装记录仍提供续签入口；应用信息页与卡片使用同一来源判定。更新来源匹配规则保持原有严格检查。
