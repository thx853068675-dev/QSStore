## 0.4.8 新增

### 重置与恢复不再丢私钥

- **删本机材料前先确认云端备份可恢复**。备份失败过去被静默吞掉，而「重置」会先删本机
  私钥再尝试恢复 —— 首次备份没成功时，这一步会永久丢掉这把私钥，重新申请还要占一个新
  槽位。现在校验不过就原样保留本机身份并说明原因。
- **备份证书已从 AGC 账号中消失时也保住私钥**。原来直接抛错，私钥留在文件系统里但不再
  被引用；现在先确认私钥可解析、必要时落盘，并记录备份版本，由用户显式「准备签名身份」
  去查替代证书或续期。登录恢复本身不申请新证书。
- **本机私钥无法解析时不再删除重建**，改为保留原文件并提示，避免一次读取抖动就换掉身份。
- **过期证书不再被当作可用身份**。过期后签出的包设备会拒绝安装，现在会走正常流程去找
  同一把私钥能配对的另一张证书；用户主动续期时还可以跳过即将过期的证书。

### 不因服务抖动多占证书槽位

- 「暂时无法核实」与「确认没有身份」分开处理：核实失败、证书下载失败、材料读取失败都
  直接停下并提示重试，**不会**继续申请新证书。只有每一张现有证书都确实下载并比对过，
  才认为配不上。AGC 调试证书槽位是团队共享资源，`DEBUG_SLOT_LIMIT` 为 3。

### 备份带版本号，可安全轮换

- 服务端 `signing_identity` 增加 `revision`，启动时自动迁移旧库，不改动已保存的私钥。
- 轮换必须提交**本机切换前已确认并持久保存**的 `replace_cert_id` + `replace_revision`，
  服务端原子替换并递增版本，冲突返回 `409 IDENTITY_CONFLICT`。这样既能让旧证书被删或
  过期后换掉备份，又能挡住旧设备覆盖新设备，并防住 ABA 回退。
- 客户端只在本机保存版本号，**不把私钥复制进 preferences**；备份失败不更新本机期望值，
  失败提示也不会被清掉。
- 相同证书与私钥的重试是幂等的。

> **部署顺序：先服务端，再客户端。** 旧客户端仍可读取与首次备份；不携带 revision 的
> 旧式轮换会被拒绝，因此无法覆盖新设备的备份。

### 超时不再提前放锁

- 超时只结束界面等待，**互斥一直保留到实际执行真正退出**。过去超时即放锁，重试会与仍在
  后台跑的下载/签名/安装并发，两边都写完成状态，设备上还可能装两次。
- 界面在超时时补一句「本次执行仍在后台收尾」，用户不会以为可以立刻重试却只收到
  「正在执行」。
- 同步抛错也会释放锁；底层若永久挂起，同进程内不会启动重复任务。

### 已安装状态不再误判

- `getBundleInfoSync` 查询其他应用需要权限。清单此前只声明了 `INTERNET`，权限错误被当成
  「没安装」，于是外部安装（没走本应用）的应用识别不到，有安装记录的还会一直显示「更新」。
- 现在声明 `ohos.permission.GET_BUNDLE_INFO`，并把结果分成三态：已安装版本 / 确认未装 /
  **无法核实**。只有「包不存在」才算未装；无法核实时回退到 HDC 查询（不需要权限），
  拿到确定答案前不显示「更新」。

### 删除闲置证书不再被死锁

- 删除前判断的依据从「本机有没有可用身份」改成**只针对本机私钥**：只有「私钥还在，且这
  是它能配对的最后一张证书」才拒绝。换机后或身份过期时本机没有私钥，删任何证书都不会
  削弱本机能力，此时必须允许清理槽位 —— 否则槽位满了又没有本机身份时，界面让用户删、
  删哪个都被拒。

### 构建与诊断

- **CMake 改为每次原生构建都跑 Cargo 增量检查**。原来用 `add_custom_command(OUTPUT/DEPENDS)`
  手工维护依赖子集，改 Rust 源码后静态库可能不重编，链接进去的是旧实现。现在由 Cargo
  跟踪全部依赖（含 path crate 与 build script）。
- **修正文件打开标志**：不再把 Unix `0600` 权限位混进 `OpenMode`（那是打开标志，不是权限）。
  材料仍只写入应用私有沙箱。
- **原生 `keyMatchesCertificate` 失败时带出具体原因**。过去只回一句
  `Cannot verify key and certificate`，无法区分「确实不配对」和「材料读不了」。
- 错误文案统一经 `errorText()`，ArkTS 里 `String(error)` 得到 `[object Object]` 的 28 处
  改为带错误码的可读信息。

### 上架类型从 9 个扩到 30 个

- 上架时可选的应用类型由 9 个（工具、开发工具、效率、影音、游戏、教育、生活、
  系统工具、其他）扩到 30 个，新增社交通讯、摄影录像、阅读、新闻资讯、出行导航、
  购物、财务、健康运动、医疗健康、美食菜谱、育儿母婴、儿童、无障碍、政务民生、
  学习、办公、企业应用、个性化、安全隐私、实用工具等。
- **原有 9 个取值全部保留**：线上已有记录的分类必须仍能提交，否则老应用改分类会被
  `INVALID_CATEGORY` 拒掉。
- 自动识别（按仓库 topics 与简介）同步扩展，覆盖全部新增类型。识别结果直接落在
  白名单内，用户不需要手动改。有测试守住「关键词表产出的分类必须在白名单里」这条
  不变量，避免出现「建议分类选不了」。
- 纯服务端改动，客户端无需更新即可看到新类型（列表由 `/submit/prepare` 下发）。

### 发现页下拉刷新

- 发现页支持**页面下拉刷新**：重新拉取第一页，带上当前搜索词，与重新进入发现页一致。
- 内容不足一屏时也能下拉。原来列表拉不动，下拉刷新与「滚到底加载下一页」都触发不了 ——
  服务端只有两三个应用时正是这个情况。现在用
  `edgeEffect(EdgeEffect.Spring, { alwaysEnabled: true })`，不再靠补占位项撑高列表。
- 刷新失败时**保留已加载的列表**，仍可继续浏览；错误态提示改为「下拉可重新加载」。
- 修了三处真实缺陷：
  - `Refresh` 嵌在 `if/else` 里时下拉手势不会被它接管，现已提到最外层，加载态与错误态
    改为列表项，列表始终存在；
  - `.onReachEnd`（触底加载）此前挂在 `Refresh` 上而不是 `List` 上，实际不生效，现已归位；
  - `loadApps` 原来在请求**发出前**就把页码与总数清零，失败一次就丢掉分页状态；改为成功
    后才提交新页码。图标下载补上请求序号与搜索词守卫，晚到的图标不会再覆盖新一轮结果，
    多余的解码像素会被释放而不是塞进列表。

实机 `3BH0224320005595`（Pura 70 PRO，HarmonyOS 6.1 / API 24）已验证：

- 外部用小白安装、没有本应用安装记录的 `com.tonghongxiang.quietstart` 正确显示「打开」；
- 「证书重置」在云端备份校验通过后真正删本地材料并重新取回，证书 ID 不变；
- 「管理 AGC 证书」能列出占满槽位的 3 张证书，在用证书即与本机私钥配对的那张。

**仍需单独验收**：

- 「超时后重试」「备份版本冲突」「删除在用证书」需要人为造场景（服务不可用、并发重试、
  另一台设备先改备份），本轮未在实机执行。
- **下拉刷新的手势本身未在实机验证**。`uinput -T -g` 模拟的拖拽始终没能触发 ArkUI 的
  `Refresh`（同一手势点搜索框能唤起键盘，说明触摸事件确实到达了应用），因此只做到
  「代码契约由 8 项测试覆盖 + 制品安装启动正常」，没有「真手指下拉出现转圈并重取」的
  实机证据。请第一次上手时留意这一点。
