# 服务端上架预处理与下架归属修复（2026-10-01）

## 兼容范围

仅修改服务端，保留现有 prepare / confirm 接口和响应结构，现有 0.4.48 客户端无需重新安装。客户端、图标候选和 GitHub Release 制品不在本次部署范围。

## 上架耗时

- 检查仓库只获取 GitHub 仓库信息、Release 索引和 HAP 文件选项；复用同一摘要已经验证的应用身份。请求不下载 HAP。
- 确认上架在一个数据库事务内写入应用、所选文件、分类、上架账号和持久化后台任务，立即返回。
- 后台单工作线程下载并解析所选 HAP，再补齐名称、图标、包名、版本及历史文件。尚未解析的新应用可能短暂显示仓库名或占位图标，下次读取列表即可获取补齐结果。
- 同仓库检查合并并复用五分钟缓存。GitHub 索引请求单次超时为五秒；上游异常时，已知仓库可使用六小时内的可信索引，保留原索引时间。全新仓库仍需成功读取 GitHub。
- 每账号每分钟三次检查的限制保持不变。

## 后台可靠性

- 任务随上架事务落盘；服务重启会恢复未完成任务。
- 失败最多尝试四次，重试间隔为 15、30、60 秒；失败不撤销已完成的上架。
- 重复确认同一草稿不会重复创建任务。旧任务结果不能覆盖更新的选包操作。
- 下架后任务不重新发布应用；后台采集保留用户选择的分类。定期采集跳过已有活动任务的应用。

## 下架后重新上架

- 已下架仓库不再被原上架账号独占，其他通过验证的账号可以重新上架。
- 重新上架沿用应用 ID，保留评论；发布成功后更新上架账号。
- 正在上架的仓库仍受归属校验保护。两个账号同时争取一个已下架仓库时，只有一个可以成功；其他账号不能修改或下架胜出账号的应用。
