# 手动续签第一步（2026-10-03）

本文记录第一步的实现及当时实机证据。后续手动入口移到管理卡片的中央弹窗，新尝试保留独立任务记录；签名冲突经用户明确确认后允许卸载重装。当前实现与验证见 MANAGEMENT-RENEWAL-UI-20261003.md。

## 已实现

- 管理 → 已安装 → 应用信息新增「手动续签」，进入独立页面并选择原 HAP / APP / ZIP。
- 普通本地预览识别到同版本已安装应用时，提供「安装」「续签」两种操作。
- 续签必须核对本机包名、内部版本号、签名身份和系统安装时间；选错包不会提交。
- 为每次续签保存独立请求标识，申请并验证新 Profile；重试复用本次已核验材料，避免重复申请。
- 已知原授权到期时间时，新有效期必须严格晚于它。实际有效期取 Profile 与证书到期时间的较早值。
- 现有证书不足以延长期限时，使用既有私钥查找或申请更晚到期的证书。槽位满或配对无法核实时停止，不自动删除旧证书。
- 续签不允许卸载重装。预检或系统拒绝覆盖时保留旧应用及数据。
- 同版本号不能代表续签完成。提交后核对系统 updateTime 增加、版本一致、签名证书指纹一致，才显示完成及新到期时间。
- 续签标识、准备状态、旧/新到期时间和安装基线写入任务数据库，旧库自动补列，任务可恢复。
- 新一次本地导入清除旧的清除数据确认，避免把历史同意带到当前操作。
- 终止失败后提供「重新选包」，保留已知原期限；可恢复任务继续使用原续签请求。

## 边界

- 续签仍需要可重签的同版本安装包。已安装的受保护目录不等于能读取原包。
- 其他工具安装的应用可能无法读取原 Profile：此时不虚构原有效期，可申请并显示经验证的新授权期限，但不声称与未知原期限相比延长了多久。
- 签名兼容性由证书或 AGC appIdentifier 预检，最终仍由系统安装器裁决。既有「派音 王之蔑视1」跨工具覆盖证据见 CROSS-TOOL-RENEWAL-20261003.md。
- 首步没有后台定时任务，也未实现商店源包自动取回。续签完成后原缓存仍按现有规则清理，下一次本地手动续签需再次选择原包。
