# 管理页签名与安装操作验证

## 本次修改

- 已安装应用、安装队列复用发现页的 `CatalogAppTitle`：名称和紧凑反色版本标签同排，长版本按实际省略文本收紧宽度。
- 卡片第二行显示签名到期时间，紧跟商店续签或本地手动续签；去掉“上次续签至”和应用信息页的两个续签按钮。
- 更新项稳定置顶；有效期进入七天内或已经过期时使用粉红卡片，深色主题有独立配色。
- 已安装刷新按钮左侧新增一键更新：使用当前渠道的更新结果，跳过已有任务，重复点击合并，逐个提交到既有 FIFO，单项失败不阻断其他提交。
- 安装队列移除操作按钮，长按卡片打开系统菜单，按任务状态提供继续安装、前往登录、任务信息和取消并清理。菜单打开前及选择后都核对实时任务；期间任务完成后，不执行旧快照中的取消。
- 最新失败任务保留在队列中，可重新续签或清理；新尝试使用独立请求与文件路径，不覆盖旧成功记录和授权证据。较旧成功记录的清理时间不会遮蔽新失败。
- 商店续签先选择自动取原包或自选同版本原包，再打开管理页中央弹窗；关闭不取消已经开始的任务。已有续签任务直接重新打开进度，已安装卡片保留并显示“续签中”。
- 签名身份不兼容时等待用户确认是否清除数据并续签。取消不卸载；批准绑定当前版本、证书指纹和 appIdentifier，传包后再次核对，身份改变必须重新确认。已经批准的卸载重装若中断，可恢复新包安装。
- 续签入口的触摸区域向下延伸，避免遮挡名称与版本标签的详情入口。

## 到期时间的来源

- 原生校验 Profile CMS 后，读取其 `validity.not-after`，用官方 Certificate Kit 解析其实际签包证书，取两者中较早的期限。
- 新安装保存有效期、系统安装更新时间和证书指纹。后续版本、指纹或更新时间改变时，旧期限不再套用。
- 旧记录只接受版本、证书指纹、不可变安装阶段时间与设备更新时间相符的完成记录，并核对保留 Profile 的 SHA-256。
- 系统签名查询受权限限制时，复用已有无线调试扫描中的签名身份，随现有设备清单持久化；没有新增逐应用 HDC 请求、AGC 请求或服务器采集。
- 缓存身份用于展示，不替代续签与覆盖安装的实时安全预检。其他工具安装且没有可核对 Profile 的应用显示“签名到期未知”，仍可手动续签。

## 关联子仓

- 上架应用配置增加子仓检查、关联及解除。服务端检查实际包名、正内部版本号及已解析附件；有歧义或与主仓包名不符时拒绝关联。
- 子仓 Release 与主仓合并，以仓库和 tag 联合标识，版本旁展示主仓 / 子仓；不同仓库相同 tag 不互相覆盖。
- 目录按包名取最新包，子仓只更新一个包时不丢失主仓其他包；星星和下载数合计，共享子仓只采集一次。
- 校验草稿、归属及分类更新在事务中核对；现有其他用户上架的子仓不转移归属。历史原始元数据共享，目录批量读取没有逐应用增加数据库查询。
- 本地服务端完整测试 153 项通过。生产服务器尚未部署这些接口；客户端检测旧服务器未保存子仓时会提示，不能将此次本地测试当作线上关联已生效。

- 原搜索框在普通 Stack 上设置 systemMaterial，7.0 实际未呈现预期的沉浸光效。API 26 改用官方 Popup 的 ImmersiveMaterial，与已经实测的回到顶部材质承载方式一致。

- API 25 及以下沿用组件模糊材质，不把 7.0 的实际渲染结果推广为所有设备已验证。

- 7.0 当前轻启 `1.2.0 / 120000` 的 appIdentifier 是 `6918743643075471637`，证书指纹 `2D3D9C80…ADB3DEF9`；此次新授权 appIdentifier 为 `6918741954949877575`，证书指纹 `009EB8ED…738FE0A4`。两项均不同，当前安装器没有找到可复用的对应身份，因此不能承诺保留数据覆盖。
