## 0.4.9 新增

### 安装任务状态收归一处

- 新增 `jobs/InstallTaskState.ets`：进程内唯一的任务视图，阶段取自落盘记录、进度取自
  下载器、执行状态取自调度器，页面通过订阅消费。
- **发现页、详情页、管理页此前各存一份 `activeJobId`/`activeInstallId`**，各自都能通过
  自己的检查，于是同一个任务可能被两个页面同时跑一遍（授权、签名、安装各做两次）。
  现在三处读的是同一份快照，进度百分比也一致。
- 页面不再是锁。按下安装后离开页面再回来，按钮不会停在旧进度上：状态来自订阅，
  不是页面自己的 `downloadBusy`。

### 状态一致性与竞态

- 暂停类状态（等待设备、等待账号、等待网络）在三处显示一致，并正确释放「正在执行」。
- 超时后**每个页面都保持忙碌**，直到那次执行真正结束 —— 与 0.4.8 的「锁保留到实际
  退出」是同一条语义，现在对订阅者也成立。
- 同一应用的「正在安装的更新」优先于「已装的旧版本」显示，按包名匹配时同样成立。
- 只有成功落盘的保存才会广播；快照不会被未保存的改动带着走，避免界面显示一个
  数据库里并不存在的状态。
- 取消订阅的页面不再收到事件；新打开的页面立刻拿到当前状态，不用等下一次变更。
- 移除记录不会让旧记录复活，也不会把字节进度重置回 0。

**仍需单独验收**：

- 「超时后重试」「备份版本冲突」「删除在用证书」需要人为造场景（服务不可用、并发重试、
  另一台设备先改备份），本轮未在实机执行。
- **发现页下拉刷新的手势本身未在实机验证**。`uinput -T -g` 模拟的拖拽始终没能触发
  ArkUI 的 `Refresh`（同一手势点搜索框能唤起键盘，说明触摸事件确实到达了应用），
  因此只做到「代码契约由测试覆盖」，没有「真手指下拉出现转圈并重取」的实机证据。
- 本轮 0.4.9 制品的实机安装复验因设备通信中断未完成。
