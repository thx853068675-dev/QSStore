# 设备安装提交自动恢复

## 问题与确认范围

用户反馈 51 签装偶发出现类似 “check diff” 的错误，手动继续后成功；尚未取得完整错误或实机复现，不能确定其对应 `CheckDir`、传输摘要差异还是签名身份差异。

源码确认两处恢复缺口：普通设备安装提交失败后直接暂停；HDC 在等待 `AppBegin` 时仅允许唤醒消息，会把正常信息或设备错误变成 `Expected AppBegin, got KernelEcho`，丢失原始原因。

## 修改

- 等待 `AppBegin` 时允许信息消息，保留设备的最新诊断，移除 `KernelEcho` 的级别字节；失败级别、关闭与超时仍返回错误。等待使用固定总时限，不被信息消息延长。
- 单 HAP 每次传输使用独立设备临时文件名，避免与其他工具或遗留任务的同名文件冲突。系统安装成功仍由实际安装状态确认。
- 仅已识别的短暂目录检查、传输摘要差异和连接/响应错误允许一次自动恢复；恢复只重新提交已有签名包，不下载、申请证书/Profile 或重新签名。
- 重复提交前先核对设备结果。普通升级核对版本；同版本编辑额外核对新的更新时间及目标证书；续签使用已有授权替换判定。结果无法读取时停止重试。
- 权限、空间不足、文件缺失、签名/证书/Profile 拒绝、非零系统安装错误码，以及没有明确识别的 `check diff` 不自动重试。不跳过签名、设备授权或传输摘要校验。
- 自动重复限定为早期失败（首次提交起 30 秒内）。长时间超时先核对结果，不再额外开始一次五分钟安装。取消及断线均保留现有处理。
- 卸载重装的破坏性步骤保持单次提交，不纳入自动重复。

## 本地验证

- 客户端行为测试 623 项通过，覆盖一次恢复、连续失败、真实拒绝、收据丢失、同版本旧安装不能误确认、取消、断线、已耗尽时间及无法核对结果。
- HDC 19 项、Rust 签名桥 13 项通过；覆盖信息后开始传包、诊断保留、授权拒绝、失败不能被后续开始消息掩盖和固定等待期限。
- 全量 ArkTS/原生构建及递归无签名检查；候选包与日志在 `/tmp/qingqi-install-recovery-20261004/` 及 `/tmp/qingqi-install-recovery-*-20261004.log`。
- 本次未做实机复现，未发布或替换 51 Release。候选包沿用当前版本信息，仅用于本地构建校验。
