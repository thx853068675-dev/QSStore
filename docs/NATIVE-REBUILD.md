# 轻启·安装器原生重构方案

## 目标与边界

最终交付一个不依赖 Flutter、Dart 或原有闭源签名库的 HarmonyOS 客户端。界面由 ArkTS/ArkUI 实现，HAP 解析和签名由可审计的原生模块实现，设备连接由独立的 HDC 适配模块负责。沿用现有商店服务协议、应用包名和用户数据语义。现有 Flutter 版本保持可构建，直到原生版本通过下列验收门槛。

当前客户端约 1.4 万行 Dart。发布包包含 `libflutter.so`、`libflutter_accessibility.so`、`libapp.so`、`libgo_signer.so`、`libsigner.so`、`libhdc_z.so`、`libunhap.so`、`libnative_core.so` 和 `libc++_shared.so`。前 3 个随 Flutter 退出；后 5 个按能力迁移；`libc++_shared.so` 是工具链运行库，是否保留取决于原生模块链接方式。

## 目标结构

```
native/
  entry/src/main/ets/
    pages/              ArkUI 页面：发现、本地、管理、我的、详情、引导
    data/               服务协议、模型、缓存、账号状态
    jobs/               持久化安装任务与恢复调度
    platform/           AccountKit、ArkData、文件选择、系统跳转
  entry/src/main/cpp/
    hap_core/           ZIP/HAP 解析、流式重打包、签名、验签
  hdc_transport/        Rust 源码版 HDC TCP 主机与协议
```

服务端继续负责应用索引、上架预处理、评论、签名身份的加密备份。客户端从 HAP 自身读取真实包名、版本和权限；服务端字段只用于展示与下载。账号私钥不写入日志，原生签名模块只读取应用沙箱内的密钥材料。

## 现有数据迁移

旧版把 `sign_material.json`、`agc_auth.json`、证书链、Profile 和私钥存于应用的 `context.filesDir`。正式版沿用原包名和签名后，应先只读解析并核对私钥/证书配对、有效期、账号及本机 UDID，再原子写入新的材料索引。迁移成功前保留旧文件，绝不因原生客户端首次启动而自动申请新证书槽位；校验失败时提示恢复现有身份或等待账号状态，而不是反复申请。预览版使用不同包名，无法直接访问旧版沙箱，这项迁移必须在正式切换包上验收。

## 安装任务与自愈规则

每次操作有稳定的 `jobId`、应用/附件身份、SHA-256、目标版本、阶段、重试次数、最后错误和文件路径。任务元数据先持久化，再执行下一阶段；阶段结果写入临时文件并校验，最后原子提交。

```
queued → downloading → verified → package_inspected → profile_ready
       → signed → signature_verified → awaiting_device → installing
       → installed
```

任何阶段均可进入 `waiting_network`、`waiting_account`、`waiting_device`、`retryable_error` 或 `terminal_error`。恢复调度根据实际文件哈希、Profile、证书和设备安装版本重新确认状态，不能只相信数据库阶段字段。

- 下载：保留 `.part` 和 ETag/长度；服务器支持 Range 时续传，否则重新下载。完成后校验服务端可信摘要，校验前不进入签名。
- 证书：优先复用与私钥配对且仍有效的证书；仅在证据证明不可用时申请新槽位。按账号和包名复用 Profile；AGC 拒绝时保留任务等待，不循环申请。
- 签名：写入独立工作目录的临时包；原生工作模块崩溃不破坏原包或上次已验签产物。以官方工具生成的标准包和真实 HAP 做差分验证，再替换现有 Go 签名器。
- 设备：仅在需要安装时检查 HDC；端口变化时暂停在 `waiting_device`，重新连接后接着安装，不重新下载/申请证书/签名。
- 安装：HDC 返回未知或超时时先查询设备上的包名与版本，确认结果后再决定重试；不盲目重复安装。自更新使用同一套查询与恢复规则。
- 清理：已完成/明确取消的任务按保留期清理。暂停或可恢复错误不得在 `finally` 中删除已校验 HAP。

“自愈”只覆盖可恢复的网络、进程与连接故障。用户关闭无线调试、取消设备授权、AGC 拒绝权限或证书槽位耗尽时，任务应保存进度并给出最少操作提示，不伪造成功，也不无限重试。

## 迁移顺序与门槛

1. **原生基座**：独立 ArkUI 客户端、系统 `HdsTabs`、四个页面路由、统一服务客户端、错误与任务模型。能编译运行，且不加载 Flutter 库。
2. **可恢复下载和本地 HAP**：商店列表、详情、历史版本、本地选择；持久任务、SHA-256 校验、进程重启恢复。与现有服务响应契约一致。
3. **账号和管理**：Huawei AccountKit/AGC 登录、头像、上架预处理/确认、评论评分、我的应用管理；不在迁移过程中更改服务端接口语义。
4. **签名核心**：自有源码的 ZIP/HAP 流处理、密钥/CSR、Profile 预检、签名与验签；使用黄金样本、畸形输入、含小型 ELF 的 HAP、大包和设备安装验证。未通过时保留旧版，不以填充 ELF 作为永久方案。
5. **HDC 与切换**：独立连接模块、超时/重连/安装结果核对；验证 6.1 与可用的 7.0 设备、断网、端口变化、AGC 故障、应用自更新。功能和签名兼容性达到旧版后，使用现有 bundleName/签名材料切换，移除 Flutter 及旧 `.so`。

每个阶段都需：ArkTS/NDK 编译、逻辑测试、真实 HAP 样本验证、必要的实机交互记录。性能用相同包比较安装耗时、峰值内存、下载重试量和包体积；不凭框架选择宣称更快。

## 本分支约束

本分支在独立包名下验证原生功能。切换现有发布应用、删除 Flutter 工程必须等正式包身份迁移、自更新和设备回归门槛满足。
