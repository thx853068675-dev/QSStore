# 发现页交互与版本频道修订

## 滑动与下拉

- 滚动位置原来写入整页状态；列表刷新渲染还会同步查询 BundleManager。
- 标题、搜索和刷新指示拆成顶部组件，用 `@Track` 只通知有关字段；标题完全收起后不再重复写滚动状态。
- 卡片渲染读取已观察的版本缓存。前台刷新、主动识别和安装完成仍读取真实系统状态，不靠历史记录猜测。
- 标题和搜索框移到 Refresh 外部。下拉只移动列表；刷新指示位于搜索框与卡片之间。
- 标题完全展开后才允许下拉刷新；滚动距离超过 240 vp 时显示“回到顶部”，点击立即回到列表起点并恢复大标题。
- 自适应标题高度仅在完全展开时测量，避免裁切时的尺寸回调逐帧缩短标题，导致回顶仍看不到标题。

6.1 设备 `3BH0224320005595` 的同一组三次滑动（速度 400 px/s）追踪：

| 指标 | 修订前 | 修订后 |
| --- | ---: | ---: |
| `JSView: ExecuteRerender` 标记次数 | 334 | 0 |
| `FlushDirtyNodeUpdate` 累计耗时 | 91.15 ms | 9.02 ms |
| `FlushDirtyNodeUpdate` P95 | 0.35 ms | 0.04 ms |
| `FlushLayoutTask` 累计耗时 | 319.41 ms | 277.50 ms |

这是一次受控手势的追踪结果，零标记不代表零绘制，也不代表所有页面或设备的帧率。
真机下拉截图确认标题和搜索保持原位，指示位于搜索下方；卡片随下拉移动。回顶前后搜索框坐标均为 `[209,455][1156,604]`，大标题完整恢复。

## 频道与安装状态

- 每个应用的频道和最新安装目标统一由 `ReleaseChannelRegistry` 管理，发现、详情和管理读取同一目标。
- 本地保存频道及预览目标；旧的仅布尔值偏好可迁移。只为用户已选预览的应用请求已有版本，合并并发，并保留失败前的目标。
- 切换频道不改写正在运行或排队的安装任务；新页面先显示该应用的真实任务。
- 空预览频道显示“暂无预览版本”，禁用安装；不能悄悄使用正式包。
- 安装判断使用真实 HAP 内部 `versionCode`：高版本更新；已安装编号等于或高于当前频道最新包时打开。手动选择更旧历史包时提示并禁用降级。
- 在线任务提交安装前再次核对设备版本，防止排队期间被其他来源升级后走卸载降级路线。本地文件安装流程保持原有范围。

真机确认：已安装构建高于频道最新包时，发现页与详情显示“打开”；切换预览后发现与详情显示相同预览目标；ClashBox 的空预览在头部、底部按钮与发现页一致禁用，重启后偏好仍保留。
更高版本更新队列及频道切换保留任务由实际页面方法回归测试覆盖。

## 服务端采集

- 频道严格按 GitHub `prerelease` 字段，Beta/RC 名称不推断频道。
- 分页采集有上限；后续分页失败或超限不会提交残缺快照并误删历史。
- 保持每轮三条发布的解析预算，优先最新正式、最新预发布和其他预发布。
- 同仓库已核验的旧预发布可保留不同实际包名，客户端按包名识别，不把它当作正式包的覆盖升级。
- GitHub 老附件缺少 digest 时，只允许官方 HTTPS 直连取得包并计算摘要，镜像不能提供可信摘要。

生产端确认 Legado 的两条 GitHub 官方预发布均有已核验的 HAP 元数据。`Beta-26042323` 实际包名是 `com.legadoTeam.app`，当前正式包是 `com.legado.app`，原有选包过滤也是预览附件消失的原因。
