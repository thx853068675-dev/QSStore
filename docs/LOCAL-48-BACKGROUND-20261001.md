# 48 预览版之后的本地修改

本轮最初按用户要求保留在本地；随后获准与 APP/ZIP、多包上架功能一起更新到 0.4.48-preview.1。最终发行制品与验证见 [发行说明](RELEASE-0.4.48-preview.1.md)。

## 页面

- 详情安装按钮的原生胶囊进度端部圆角为 26vp，而按钮为 18vp，产生边角底色露出。改用全高度线性填充，由外层按钮统一裁切，保留原生平滑进度。
- 详情滚动区域延伸至透明状态栏下，内容起始位置保留安全间距；返回键和「应用详情」固定在顶部，渐变模糊随前 32vp 滚动逐渐显现，下端淡出。实际原生 Stack 需要明确定位，已经用实机核对并修正。
- 发现页普通卡和星光卡的标签 Flex 按交叉轴居中，星数与分类、版本标签居中对齐；长标签依然允许换行。
- 安装队列操作栏缩小视觉重量：「继续安装」改为 32vp 浅蓝胶囊，外层保持 44vp 点击高度；「取消」改为无底色的次要文字，点击区域不小于 44vp。操作栏与应用信息左缘对齐，取消、清理和继续安装的逻辑及禁用条件保留。

## 后台执行

- 声明 `dataTransfer` 后台模式和 `ohos.permission.KEEP_BACKGROUND_RUNNING`，通过官方 Background Tasks Kit 申请长时任务。
- 执行器共享长时任务，页面退出不释放；最后一个实际执行结束后才停止。超时或取消只结束界面等待时，仍保持保护直至原生工作和清理结束。
- 申请失败不阻断前台安装，也不丢弃系统托管下载。系统取消后台资格时不循环申请，回前台且仍有工作才重新申请。
- 系统下载代理显示实际文件名和下载进度通知。返回前台时先读取系统下载结果；挂起后尚在下载的任务获得新的停滞观察期，完成文件不再因旧的 60 秒计时被删除或切换镜像。真正持续停滞的连接仍会失败。
- 执行超时预算按定时器活跃时间核对，检测到长时间定时器停顿时不立刻误报设备响应超时。

官方说明：[系统托管下载即使申请 dataTransfer，应用进程仍可能被挂起](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/task-management/continuous-task.md)。下载由系统继续，不能将长时任务理解为对强制停止、进程回收或无线调试断开的无条件保证。
