# 原生客户端 0.4.7 发布说明

对应提交 `944b47d` 及其后（分支 `codex/native-arkts-rebuild`）。在 0.4.5 的基础上补齐了实机使用中发现的问题。

> 0.4.6 的 Release 制品缺少下面「0.4.7 新增」一节的全部修复，已被本版取代。

**这是本机自用的候选包**：Profile 只绑定上面那一台设备，装到别的设备会被系统
拒绝。它不是对外分发包，也**不要**把它当作公开版本发布。

### 为什么只有正式包名一个制品

签名需要与该包名匹配的 AGC Profile，工作区里现在只有
`com_tonghongxiang_hapstore.p7b` 一份（`~/Documents/hap_installer/store/`）。
预览包名 `com.tonghongxiang.hapstore.nativepreview` 的 Profile 已不存在，
所以 `dist/` 里历史遗留的 preview 制品无法按同样流程重建 —— 它们保留原样，
不做改动。

`dist/qingqi-native-formal-0.4.4-device7.0-signed.hap` 补上了缺失的 `.sha256`；
文件名里的 `device7.0` 是当时写错，实机是 HarmonyOS 6.1 / API 24，0.4.5 这一版
按实际写回 `device6.1`。

## 0.4.7 新增

### 安装不再卡死

「安装到设备」这一步能挂多久不由客户端决定：设备休眠、无线调试掉线、授权弹窗没人点，
底层调用都可能一直不返回，任务就永远停在「正在安装」。三层兜底：

- **墙钟上限**：`JobScheduler.runExclusive` 给每个任务加上限（常规 4 分钟，下载 12 分钟），
  超时按失败处理并给出「等待设备响应超时：请确认设备已连接无线调试，然后重试」。
  不自动重跑——设备上那次安装可能已经生效了。
- **界面状态兜底**：新增 `onPageShow`。回到页面时，如果 `activeJobId` 指向的任务已经不在
  运行，就摘掉标记并停掉阶段轮询，按钮不再永远停在进度上。
- **任务兜底**：停在非终态且 10 分钟没有更新的任务，标成可重试（「上次安装中断了，
  点击继续安装」），管理页出现「继续」而不是一个转不完的进度。

### 检查更新

- 详情页版本记录右侧新增「检查更新」，让服务端**立刻重采**这一个仓库，不必等采集周期
  （默认 30 分钟）。服务端新接口 `POST /api/v1/apps/{id}/refresh`，按 IP 限流
  （10 次/小时）。
- 客户端另有 60 秒静默冷却：冷却期内的点击直接忽略，不发请求、不转圈、不报错。
- 检查本身也有 30 秒上限，避免它变成新的卡住点。

### 界面

- 「我上架的应用」的「刷新」文字改为 ↻ 图标，与「已安装」那处一致；刷新中显示转圈并禁止重复点击。
- 「我的」页退出账号从整条按钮收成右侧一个图标（二次确认仍在）；未登录时占位不变。
- **已安装卡片的版本号不再显示成一串像日期的数字**。`version_name` 是 0.4.6 才加的字段，
  更早安装的记录里是空的，回退到 `versionCode` 就成了 `2026092902`。现在先按版本号
  从目录匹配版本名，匹配不到（装的是旧版本时目录里只有最新版）就从 HAP 文件名解析，
  例如 `qingqi-native-formal-0.4.5-device6.1-signed.hap` → `0.4.5`。

### 本地安装的时间轴

- **不再停在上一次的快照上**。阶段轮询里有一处「阶段没变就早退」，而同一个阶段内
  `stageHistory` 仍在增长，于是时间轴停在「已核对应用身份」不动 —— 这也正是
  「装完了下面还停着」的原因。现在每次都同步任务对象。
- **「用时」不再恒为 0 / 变成天文数字**。计时基准用的是轮询写入的时间戳，轮询停掉后
  它是 0，最后一步就按 `0 - 时间戳` 算出了 29844169 分。现在基准缺失时取当前时间；
  已经结束的任务最后一步只显示时刻，不再硬凑一个没有意义的「用时」。
- 完成状态挪到流程卡片顶部（与任务名同排），不再出现在「选择 HAP 文件」按钮下面；
  删除按钮下方那行文字，以及按钮上方的说明段。

### 不再一直占着设备的调试端口

设备的无线调试基本只服务一个 HDC 宿主：轻启连着不放，DevEco Studio 和 hdc 命令行就
连不上设备。现在「我的 → 设备连接」多了一个主动释放入口，并说明了原因。

- Rust 传输层新增 `disconnect()`：协议本身没有 disconnect 类命令，所以按连接键取出
  session，drop 掉写半端即关闭链路，同时清掉连接表条目。经 `qingqi_hdc_disconnect`
  导出到 C ABI，再由 `hdcDisconnect` 暴露给 ArkTS。
- 「我的 → 设备连接」在已连接时给出「释放」按钮，点一下即释放，无需确认；释放后
  下次安装会自动重连，配对信息仍然有效，用户不用重新配对。
- 本机回环端口不再写死：首选 38710，被别的程序占用时自动改用系统分配的空闲端口，
  避免和其他调试工具撞端口。`start()` 现在返回实际监听端口，调用方用它发命令。

> 已知边界：调试链路只在真正执行 HDC 操作时建立。「安装中途退出/切后台自动释放」
> 仍未实现（会在某个任务正要继续时打断它），目前由用户主动释放。

### 采集周期

服务端 `HAPSTORE_SYNC_INTERVAL` 从 21600 秒（6 小时）改为 1800 秒（30 分钟）。之前
「刚发布的 Release 在客户端看不见」的根因就是这个：采集器只重采 `synced_at` 超过
一个周期的应用，最坏要等两轮。

## 0.4.6 新增

- **详情页安装按钮不再永远显示「安装应用」**。`loadInstalledJobs` 跑在 `loadApp`
  之前，取到的包名是空的；现在选中附件后重算。已装显示「打开应用」，目录有新版
  显示「更新到 x.y.z」。判定同时从 HDC 换成 `bundleManager`，不再依赖无线调试。
- **版本号改用版本名**（`版本 1.1.0` 而不是 `2026092902`）；已安装卡片去掉包名行。
- **本地页**：去掉底部说明、HAP 行居中、新增按时间顺序的安装流程（读取 → 校验 →
  核对身份 → 授权 → 签名 → 安装），每步带时刻与耗时。
- **搜索框常驻**，输入即搜（300ms 防抖），带请求序号守卫防止旧响应覆盖新结果。
- **服务端删掉 5 个客户端从未调用的接口**（`/categories`、`/stats`、
  `/submit/{task_id}`、`/download-event`、`/report`）及其处理器与数据层函数。

### 性能

目录卡片原来要为**每个**应用单独请求一次 `/releases`，一屏 30 个应用就是 31 次
往返；更新检查更重，每次切页都重跑。现在：

- 服务端在 `/apps` 列表里直接带 `latest_asset`，一次请求解决整屏的
  「装没装 / 要不要更新」；
- 更新检查改为纯本地算术（目录版本号 vs `bundleManager` 查到的本机版本），
  零网络零设备查询；
- 「装没装」不再依赖无线调试 —— 原来关掉无线调试时，轻启连自己已经装了都判定不出来。

提交：`b0ff8cc`（服务端）、`9d32415`（客户端）。

### 交互

- 目录卡片右侧是真正的动作按钮：安装 / 更新 / 打开，按钮自己显示下载进度；
- 卡片主体跳详情，按钮独立响应（原来整卡的点击会吃掉按钮的点击）；
- 上架入口从发现页移到「管理 → 我上架的应用」下方，发现页右上角改为**搜索**；
  搜索走服务端 `q` 参数，不是只筛已加载的那一页。

提交：`9d32415`、`eb1f964`。

已验证：

- 目录卡片显示「安装 / 打开」，点安装确实入队并下载了 6.6 MB 的 HAP；

- 搜索 `quietstart` 返回 1 条结果，与服务端 `q` 查询一致；

**仍需单独验收**（需要另一个华为账号或人工造场景，详见

进度、同步卸载。
