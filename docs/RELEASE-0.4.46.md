# 轻启·安装器 0.4.46

## 修复轻启工作模块导入

0.4.45 的原生安装链路只重签轻启主 HAP，内嵌的 `entry_test` 工作模块仍保留发布者签名。轻启启动后单独安装工作模块时，系统要求它与已安装主包同签名，因此其他用户会看到工作模块导入失败。此前 Flutter 签名器的分层重签逻辑并未进入原生安装链路。

现在签名器识别轻启整包，核对内嵌工作模块的包名、版本和摘要，先用本机证书与设备 Profile 重签工作模块，再更新主包内的摘要清单并重签主包。产物中的两个 HAP 使用同一证书和 Profile；其他 ZIP 条目的内容保持不变。材料或结构不匹配时在安装前报错，不把只签了主包的产物交给设备。

## 验证范围

- Rust 分层重组回归测试通过；轻启 1.2.0 真实 HAP 经分层重签后，主包和工作模块均通过官方 SDK `verify-app`，证书与 Profile 摘要相同，清单 SHA-256、大小与工作模块一致，其他条目内容未改变。
- 全量构建执行 33/33 任务，原生库摘要与 0.4.45 不同。0.4.46 HAP 通过官方 SDK 验签。
- HarmonyOS 6.1 设备 `3BH0224320005595`：安装器 0.4.45→0.4.46 覆盖安装、启动和版本核对通过。设备上已有的轻启主包采用另一张证书，单独安装测试工作模块被系统以 `9568322` 拒绝；这不能代替同一用户从安装器首次安装轻启的实机验收。

## 分发范围

0.4.46 沿用 0.4.45 的 AGC 调试证书与 Profile，只适用于其中已授权的设备。其他设备需要正式发布证书与 Profile；现有的设备专属 HAP 不能作为全用户可安装版本。
