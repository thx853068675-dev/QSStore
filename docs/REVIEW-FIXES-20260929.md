# 证书恢复、轮换与安装互斥修复

基于 `codex/native-arkts-rebuild` 的 `f4f6100` 及已有未提交修复继续处理，保留原有页面、权限和错误文案改动。

## 本轮修复

- 重置通过云端校验后刷新证书，保留原私钥；无备份、过期、身份不同或网络失败不会删除原材料。
- 确认云端证书过期/缺失时保留原私钥，显式准备签名身份可查找替代证书或续期；登录恢复不申请新证书。
- 主动提前续期会跳过即将过期的证书。证书下载、材料读取或核实失败时不会继续申请证书。
- 备份以账号绑定的本机已确认 revision 做 CAS，服务端原子递增版本，阻止旧设备覆盖及 ABA 回退；失败不更新本机期望值。
- 切换证书后同步备份；删除在用证书前先切换、再备份。备份失败后重试删除也必须通过备份检查。
- 删除判断依据实际私钥配对和有效身份，允许无私钥/过期身份清理闲置槽位，保护最后一张有效配对证书。
- 超时仅结束等待，任务锁直到原执行真正退出才释放；同步异常也释放锁。底层若永久挂起，不会在同进程内启动重复任务。
- C++/Rust FFI 错误缓冲区签名保持一致，返回具体文件读取错误，不输出私钥内容。
- CMake 每次原生构建执行 Cargo 增量检查，由 Cargo 跟踪全部 Rust 依赖。
- 修正文件打开标志：不再把 Unix `0600` 权限位混入 `OpenMode`；材料仍写入应用私有沙箱。

## 发布与验证边界

服务端接口增加 `revision`，启动时自动迁移旧数据库。**先更新服务端，再更新客户端**，具体协议见 `SERVER-API.md`。旧客户端缺少 revision 的轮换请求会被拒绝。

本轮未部署线上服务、未覆盖安装实机，也未修改设备证书。已有 6.1 实机报告只作为先前版本的证据；新版本仍需发布后补端到端验证。
